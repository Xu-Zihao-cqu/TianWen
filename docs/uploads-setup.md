# 下载统计与作品上传部署

## 下载统计（任务 3）

在 Supabase SQL Editor 执行 `supabase/migrations/20261011_download_counts.sql`。
前提：现有 profiles、blog_posts 已建好。该脚本可重复执行，不会清空计数。

- download_counts：按文件 URL 路径保存全站共享次数，所有访客可读。
- download_events：事件 UUID 去重；客户端无直接读写权限。
- record_download：已登录用户（含 Guest 匿名会话）可调用，只接收已登记的文件，原子递增，不信任前端提交的次数。
- 静态作品文件已初始化；Blog 附件新增/更新由触发器登记。未来手动添加静态文件，需要将 URL 路径插入 download_counts（ON CONFLICT DO NOTHING）。
- 按钮初次加载、浏览器重新获得焦点时刷新；同页同文件按钮同步。
- 口径是文件获取成功并触发浏览器保存的次数，无法判断用户是否最终保存到磁盘。缺失、网络失败和预览不计数；这是使用统计，不是防作弊审计。
- 无配置或表未建时显示“统计暂不可用”，不影响文件下载；不伪造本地计数。

验证：同一文件下载一次，刷新后应增加 1；缺失文件进入彩蛋页且不增加。其他账号应读到相同次数。对相同事件 UUID 重复调用 RPC，次数只增加一次。普通用户直接 UPDATE download_counts 应被拒绝。

## 作品上传（任务 4）

1. 先执行上面的下载统计迁移，再执行 `supabase/migrations/20261011_works.sql`。
2. 在已有 profiles 表中，将需要发布的用户 role 设置为 **Developer**（现有枚举是单数，不是 Developers）。不要给前端配置 service_role key。
3. 重新登录后，作品集和各作品列表会显示“上传作品”；入口为 `/works/new`。

工作流：选择四个作品板块之一 → 填写名称/摘要/标签 → 拖放或选择图片/附件 → 选择封面、调整图片顺序 → 导入 `.md` 或直接编辑 Markdown → 预览 → 发布。

- 图片支持 SVG、PNG、JPG/JPEG，单张最多 8 MB，最多 12 张；SVG 入库前去除脚本和活动标签，使用 img 展示。
- 附件支持 ZIP、RAR、7Z、PDF、DOCX（最多 50 MB），以及源码/Markdown/文本（最多 1 MB）；最多 20 个附件。
- 正文导入最多 1 MB，正文最多 100,000 字；导入会替换编辑区内容。Markdown 本地相对图片不会自动上传，需上传图片后点“插入正文”。
- 名称、摘要、正文按输入原文展示，两种站点语言共用该内容，不自动翻译。
- 首张图片默认封面，也可切换封面和调整图集顺序。上传进度按已完成文件数显示，不代表单文件字节进度。
- 本机草稿按账号隔离，保存文字与已成功上传资源；再次进入可恢复。上传或发布失败保留已完成内容。发布编号保持稳定，重试不会重复创建卡片。
- 发布写入 works 表，Storage 使用独立 work-assets 公开桶；只有 Developer 可向自己的 UID 目录上传、创建自己的作品。User/Guest 只能读，客户端不能修改计数或伪造作者。
- 详情页显示封面、图集、Markdown 与附件；上传作品会合并到现有列表和标签筛选，分类数量同步。静态作品继续保留。
- 此版本提供新作品发布，不提供线上编辑/删除。编辑器移除文件仅从草稿中移除引用，不删除 Storage 对象，避免误删正文引用；未发布资源可由项目管理员在 Storage 中核对后清理。

### 上线验收

- Developer 上传 SVG/PNG/JPG、导入 Markdown、加 ZIP/PDF 附件，选择封面，发布后刷新列表与详情，内容应仍在。
- 使用 User/Guest 访问 `/works/new` 应显示权限提示；直接尝试 INSERT works 或上传 work-assets 也应被 RLS 拒绝。
- User/Guest 下载发布的附件，应获得真实原件，并更新共享下载次数。
- 暂时断网，上传/发布应显示错误、保留表单；恢复网络后重试。
- 检查手机宽度下表单、预览、附件和图片排列；不应出现横向溢出。

上述数据库迁移与真实账号联调由站点所有者执行。本地模拟验证不替代远程 RLS 验收。
